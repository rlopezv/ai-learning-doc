# Chapter 1 — Introduction to AI Systems Engineering

[⬅ Back to Foundations](index.md)

## Context

This chapter introduces **AI Systems Engineering** as a discipline concerned with the design, integration, and operation of systems that incorporate large language models and other AI components. While early machine learning work focused primarily on model training and research experimentation, modern AI applications require a broader **systems perspective**.

In production environments, models operate within complex pipelines that include prompts, retrieval systems, orchestration workflows, data pipelines, and infrastructure services. Understanding how these elements interact is essential for building reliable and scalable AI platforms.

This chapter establishes the conceptual framework used throughout the rest of the book. It introduces the paradigm shift from deterministic software to probabilistic AI-driven systems and explains the architectural abstractions needed to reason about them.

---

## Concept Overview

Traditional software systems are deterministic: program logic fully determines system behavior. If the same input is given twice, the same output is produced.

AI systems behave differently. Their outputs are generated by **probabilistic models trained on large datasets**, meaning behavior emerges from statistical patterns rather than explicit rule sets.

As a result, modern AI systems combine multiple components:

- application logic
- prompts
- machine learning models
- retrieval systems
- orchestration workflows
- external tools and APIs
- evaluation pipelines

Together these components form a **composite system**, where behavior arises from the interaction between artifacts rather than from a single algorithm.

A simplified conceptual flow:

User Input
↓
Application Logic
↓
Prompt Construction
↓
Context Retrieval
↓
LLM Inference
↓
Response Generation

The central engineering challenge is not only building these components but ensuring that they **interact reliably, predictably, and efficiently** under real-world conditions.

**Key Concept — AI Systems Are Composed Systems**

A production AI application is rarely just a model call. Instead, it is a network of artifacts and services: prompts, embeddings, vector databases, orchestration logic, evaluation datasets, monitoring pipelines, and infrastructure. Managing this ecosystem is the core responsibility of AI Systems Engineering.

## 1.1 A Paradigm Shift in Software Engineering

Traditional software engineering is built around deterministic algorithms.

Input → Algorithm → Output

The developer specifies exactly how inputs are transformed into outputs.

However, many real-world problems cannot easily be solved through explicit rules:

- natural language understanding
- document analysis
- summarization
- conversational interaction
- knowledge extraction

Machine learning introduced a new paradigm in which behavior is **learned from data rather than explicitly programmed**.

Large language models extend this idea by providing **general-purpose reasoning capabilities** that can be configured through prompts rather than through new training for every task.

This shift transforms software architecture:

| Traditional Software            | AI Systems                            |
| ------------------------------- | ------------------------------------- |
| Deterministic logic             | Probabilistic models                  |
| Behavior defined by code        | Behavior shaped by data and prompts   |
| Unit tests verify correctness   | Evaluation frameworks measure quality |
| Algorithms implemented manually | Capabilities emerge from training     |

This paradigm shift requires new engineering methods and architectural patterns.

---

## 1.2 What is AI Systems Engineering

**AI Systems Engineering** focuses on building reliable production systems that integrate AI models as core components.

It extends traditional software engineering with responsibilities such as:

- integrating model inference into application services
- designing prompt and context pipelines
- operating retrieval infrastructure
- managing model lifecycle and updates
- evaluating system behavior
- monitoring quality and cost

The discipline sits at the intersection of several fields:

- software engineering
- machine learning engineering
- distributed systems
- data engineering
- platform engineering
- DevOps and MLOps

In practice, an AI system includes components such as:

- model inference services
- prompt management
- context retrieval pipelines
- orchestration workflows
- evaluation datasets
- observability and monitoring systems

**Key Concept — Models Are Only One Component**

In production AI systems, the model itself is rarely the dominant engineering effort. Most complexity lies in the surrounding infrastructure required to control, evaluate, and operate model behavior reliably.

## 1.3 The Convergence of Engineering Disciplines

Modern AI systems require expertise from several historically separate engineering domains.

AI Systems Engineering
│
├ Software Engineering
├ ML Engineering
├ Data Engineering
└ Infrastructure Engineering

Each discipline contributes a different capability:

- **Software Engineering** — application architecture and APIs
- **Machine Learning Engineering** — model training and evaluation
- **Data Engineering** — pipelines and data management
- **Infrastructure Engineering** — scalable compute and deployment platforms

AI Systems Engineering integrates these areas to produce **coherent end-to-end systems**.

---

## 1.4 From Software 1.0 to LLM Systems

The evolution of software systems can be understood through three conceptual stages.

Software 1.0

Code + Input Data → Output

Software 2.0

Training Data + Learning Algorithm → Model  
Model + Input → Output

LLM Systems

Model + Prompt + Context → Output

Here:

- the **model** provides general reasoning capability
- the **prompt** defines task instructions
- the **context** provides domain-specific information

System performance therefore depends heavily on **prompt design and context construction**.

---

## 1.5 New Categories of System Artifacts

Traditional software systems manage two primary artifact types:

- source code
- data

AI systems introduce additional artifact categories:

| Artifact Type       | Purpose                                |
| ------------------- | -------------------------------------- |
| Prompts             | Define instructions for model behavior |
| Embeddings          | Numerical semantic representations     |
| Vector indexes      | Enable semantic retrieval              |
| Evaluation datasets | Measure system quality                 |
| Retrieval pipelines | Provide contextual knowledge           |
| Model checkpoints   | Store trained model states             |

These artifacts collectively define system behavior and must be **versioned, tracked, and evaluated**.

---

## 1.6 The Artifact Dependency Graph

AI systems can be understood as **graphs of artifacts**, where each artifact influences system behavior.

User Query
↓
Prompt Template
↓
Retrieved Context
↓
Model
↓
Generated Response

Every node in this graph represents a **versioned component**.

Changing any component—prompt wording, retrieval strategy, or model version—can alter system output.

**Key Concept — Behavior Emerges from Artifact Interactions**

AI systems do not behave like deterministic programs. Instead, their behavior emerges from interactions between prompts, context, models, and data pipelines.

---

## 1.7 The Eight-Layer Architectural Model

To reason about AI systems at scale, responsibilities can be separated into architectural layers.

Interaction Layer  
Application Layer  
Orchestration Layer  
Prompt Layer  
Retrieval Layer  
Model Layer  
Data Layer  
Infrastructure Layer

Separating these responsibilities improves modularity, scalability, and maintainability.

---

## 1.8 The AI System Lifecycle

AI systems follow a lifecycle that extends beyond traditional software deployment.

Typical phases include:

1. problem definition
2. data acquisition
3. model selection or training
4. prompt design
5. retrieval pipeline development
6. system integration
7. evaluation and benchmarking
8. deployment
9. monitoring and iteration

Unlike conventional software systems, **evaluation and iteration remain continuous processes**.

---

## 1.9 New Engineering Challenges

AI systems introduce challenges that do not exist in deterministic software.

| Challenge             | Description                                            |
| --------------------- | ------------------------------------------------------ |
| Non-determinism       | Model outputs may vary between executions              |
| Prompt sensitivity    | Small prompt changes can significantly alter behavior  |
| Hallucination         | Models may produce incorrect or fabricated information |
| Context limitations   | Models can process limited input tokens                |
| Cost and latency      | Model inference may be expensive                       |
| Evaluation difficulty | Quality may be subjective and domain-dependent         |

---

## 📋 Chapter Summary

- **AI Systems Engineering** is the discipline of designing, building, and operating production systems where AI models are core system components.
- System behavior is defined by code _and_ prompts, datasets, models, pipelines, and experiments.
- The **Artifact Dependency Graph** explains how system outputs emerge from interacting components.
- LLM systems introduce engineering challenges such as non-determinism, evaluation complexity, and token cost management.
- The **eight-layer architectural model** helps structure enterprise AI systems.
